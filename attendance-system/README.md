# Employee Attendance System

Static frontend (GitHub Pages) → `fetch()` → Google Apps Script Web App → Google Sheet.

```
attendance-system/        ← GitHub repository
├── index.html  admin.html  style.css  script.js  admin.js  README.md
└── assets/logo.png       ← add your logo (a letter badge shows until you do)
google-apps-script/Code.gs  ← NOT uploaded to GitHub; pasted into Apps Script
```

## 1. Google Apps Script setup
1. Create a Google Sheet. Set **File → Settings → Time zone** (all timestamps use it).
2. **Extensions → Apps Script**. Paste `Code.gs`, save.
3. Select `setup` in the toolbar and **Run** (approve permissions). This creates the `Attendance` sheet (with headers) and an `Employees` sheet. **Replace the sample row with your real employees** (Code, Name, Active = Yes/No).
4. **Project Settings → Script properties → Add** `ADMIN_PASSCODE` = a strong passcode. (Optional: `ALLOW_MULTIPLE` = `true` to allow repeated check-ins.)
5. **Deploy → New deployment → Web app**. Execute as: **Me**. Who has access: **Anyone** (required so the public site can call it; access to the sheet itself stays private).
6. Copy the Web App URL (ends in `/exec`). Open it in a browser: you should see `{"success":true,"message":"Attendance API is running"}`.
7. Paste it into `script.js` as `GOOGLE_SCRIPT_URL`.
8. After **any** change to `Code.gs`: **Deploy → Manage deployments → Edit → New version → Deploy**. The URL stays the same.

## 2. GitHub Pages setup
1. Create a GitHub repository.
2. Upload the files in `attendance-system/` (not the folder itself).
3. Confirm `index.html` is in the repository root.
4. **Settings → Pages**.
5. Source: **Deploy from a branch**; Branch: `main`; Folder: `/ (root)`. Save.
6. Wait ~1 minute, then open `https://<username>.github.io/<repository>/`.

## If GitHub shows 404
1. `index.html` must be in the root, named exactly (lowercase).
2. Pages must be enabled and the build finished (Actions tab).
3. Branch and folder must match where the files are.
4. Free accounts need a public repository for Pages.
5. The URL must be `https://<user>.github.io/<repo>/` (repo name is case-sensitive in the path).
6. File names and paths are case-sensitive: `style.css` ≠ `Style.css`. All paths in this project are relative.

## If the Google Sheet is not updating
1. A deployment exists and you are using its latest `/exec` URL (not `/dev`).
2. Access is **Anyone**; you redeployed a new version after editing code.
3. The script is bound to the sheet (opened via Extensions → Apps Script) and permissions were approved.
4. Sheets named exactly `Attendance` and `Employees`; the employee exists and is active.
5. Check **Apps Script → Executions** for `doPost` errors.
6. Turn on `DEBUG_MODE = true` in `script.js` to see the URL, status codes and raw response.

## If the website says 404
Don't assume the sheet is broken. Open the Web App URL directly. If it shows the JSON above, the backend is fine and the problem is `GOOGLE_SCRIPT_URL` (typo, `/dev` URL, or empty).

## Design notes and limits
- **Time** is generated by Apps Script in the sheet's time zone. The on-page clock is display only.
- **IP address:** browsers can't reliably expose it, and Apps Script doesn't receive client IPs. The column stores a session ID, page URL, origin and user agent instead. Real IP logging needs a proxy service.
- **Requests** are sent as `text/plain` JSON to avoid a CORS preflight, which Apps Script can't answer.
- **Security:** no sheet ID or secrets are in the frontend. Admin data requires `ADMIN_PASSCODE`, checked server-side. Employee validation is name + code only; this is not strong authentication (codes can be shared). To harden later, add per-employee PINs in the `Employees` sheet and check them in `mark_()`.
- Anyone who knows the URL can attempt submissions; the Employees list limits what is accepted.
